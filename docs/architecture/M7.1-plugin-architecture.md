# SonoHUD 확장 구조

SonoHUD 0.7.2는 음악 재생, 작업 표시줄, 스펙트럼, 데스크톱 오버레이를 독립적으로 실행한다. 실제 온라인 가사 검색·후보 매칭·HTTP 통신 구현은 공개 제품 및 소스의 필수 구성 요소에서 분리했다. 기본 패키지는 가사 제공자를 동봉하거나 설치 경로를 자동 안내하지 않는다.

| 경계 | 책임 |
|---|---|
| SonoHUD.Core | 미디어·프리셋·설정과 공급자 중립적인 곡/가사 데이터. 10개 프리셋의 저장 형식을 유지한다. |
| SonoHUD.PluginContracts | API 1 계약, 초기화 문맥과 기능 인터페이스. WPF, 네트워크 서비스, 호스트 ViewModel 의존성이 없다. |
| SonoHUD.App/Plugins | 실행 없는 파일 탐색, 사용자 승인 및 지문 저장, 확장별 로드 문맥·수명, 오류 상태, 데이터 경로. |
| 플레이어·렌더러 | 활성 공급자가 있을 때만 공통 가사 패널과 전용 프리셋 세 개를 연결한다. 탐색·선택을 확장에 위임하고 반환된 텍스트를 파싱해 재생 위치와 동기화한다. 종료·비활성화·곡 변경 시 취소하며 지나간 요청의 결과를 게시하지 않는다. |
| 확장 | 자체 서비스의 요청, 재시도·식별, 후보의 순위와 선택. 코어가 제공하는 API와 값 타입만 참조한다. |

## 발견·동의·복구

설정의 **확장 설치**는 파일 대화상자에서 관리 DLL을 선택하고, 메타데이터·호환성·전체 지문을 검사한 뒤 확인을 받아 사용자 확장 폴더에 복사한다. 이 시점에 실행 코드를 로드하지 않는다. **활성화**를 누르면 이름, 버전, ID, 선언한 접근, 지문을 보여주고 다시 확인한다. 여러 파일로 구성된 관리형 확장은 **확장 폴더 열기**에서 독립 하위 디렉터리 전체를 복사하고 새로 고침하거나 다시 시작한다. 자동으로 코드를 실행하는 DLL 검색은 없다.

기본 데이터 루트는 기존 사용자 프로필 `%LOCALAPPDATA%\SonoHUD`다. 다른 시험 프로필을 지정하면 해당 루트 아래에서만 탐색한다. `Plugins/<id>/`는 실행 파일과 종속성을 담고 `PluginSettings/<id>/`는 개별 설정을 담는다. 단일 DLL은 Plugins 바로 아래에도 둘 수 있다. 프로그램 설치 폴더 및 버전 교체 폴더와 분리된다. 제거는 확장 경로의 항목을 `PluginSettings/removed/<임의 식별자>`로 옮기고 승인을 해제한다. 같은 ID로 재설치하면 저장했던 설정을 사용할 수 있고, 로컬 복구 사본은 앱을 닫은 뒤 사용자가 직접 지울 수 있다.

활성화한 번들의 지문만 `PluginSettings/approved-v1.json`에 원자적으로 저장한다. 명시적으로 승인했던 파일 내용·버전이 바뀌거나 종속 DLL이 달라지면 다시 승인을 받아야 한다. 같은 ID가 둘 이상 발견되면 어느 복사본도 실행하지 않는다. 가사 공급자 한 개만 동시에 연결하고, 다른 기능만 가진 확장은 함께 사용할 수 있다. 요구 API가 너무 높거나 낮은 상태, 실행 실패, 지문 변경은 설정에 표시한다.

초기화에 대한 사용자 승인이 완료되면 해당 확장 범위에 실행 표시 파일을 기록하고 정상 종료에서 제거한다. 이전 실행이 중단된 흔적이 있으면 다음 시작에서 자동 활성화를 중지한다. 앱을 열 수 없는 경우 앱을 닫고 문제가 된 확장 폴더를 Plugins 밖으로 이동한 뒤 다시 시작할 수 있다. 정상 응답이 없는 확장 코드, 자체 네이티브 호출, 프로세스 종료 요청을 같은 프로세스 내에서 강제로 격리할 수는 없다.

## 로딩 설계

PEReader가 ECMA-335 사용자 지정 특성의 데이터만 읽는다. 승인 전 생성자, 모듈 초기화, 반사 실행을 수행하지 않는다. 수집한 파일명·길이·내용으로 번들 SHA-256을 계산한다. 활성화 직전에 다시 읽고 확인한 동일 바이트를 collectible AssemblyLoadContext에 넘긴다. 종속 라이브러리도 이 스냅샷에서 로드한다. 공용 SDK와 Core 타입은 호스트 인스턴스를 공유한다. 이 릴리스는 평탄한 관리형 DLL 묶음을 지원한다. 절대 경로 재탐색이 가능한 일반 AssemblyDependencyResolver 대신 승인한 동일 바이트를 사용하는 이유다. 비활성화 시 진행 중 검색을 취소하고 Dispose 후 Unload를 요청한다. 정적 참조·작업 스레드가 남으면 실제 수거는 늦어질 수 있다. [Microsoft 플러그인 지침](https://learn.microsoft.com/en-us/dotnet/core/tutorials/creating-app-with-plugin-support) · [로드 문맥](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext) · [협력적 언로드](https://learn.microsoft.com/en-us/dotnet/standard/assembly/unloadability)

확장은 앱과 같은 Windows 권한으로 실행된다. 선언한 권한은 UI의 고지이며 OS의 권한 제한이 아니다. 파일 지문은 승인한 복사본의 변경을 감지하며 발행자 신원이나 안전성을 보증하지 않는다. 출처를 신뢰하는 확장만 활성화한다.
