# v1.0.0 공개 승인 체크리스트

대상은 Revo-32/sonohud의 Stable 채널이다. 공식 URL은 https://github.com/Revo-32/sonohud/releases 이며 최초 공개 이전에는 다운로드가 없을 수 있다.

### 승인 전

- [ ] 공개할 Git 트리는 검증한 대응 소스 ZIP의 파일로만 구성한다. 로컬 제품 작업 폴더나 증거 폴더를 통째로 올리지 않는다. 소스와 SHA256SUMS의 **정확한 지문**, 커밋, 공개키 ID, 버전을 승인 기록에 남긴다.
- [ ] 릴리스 서명 담당자가 별도 계정·기기의 암호화 백업과 복구 경로를 인수한다. 공개키 지문은 독립된 보관 기록과 대조한다. [키 관리](M8.1-signing-key-policy.md)
- [ ] 설치기, Portable, 대응 소스, full.nupkg, releases.stable.json, 그 .sig 및 SHA256SUMS.txt 7개를 지정한다. `python scripts/check-manifest.py <폴더> --signed`와 `Sign-ReleaseFeed.ps1 -VerifyOnly`를 함께 실행한다. 수동 서명 후 빌드를 다시 하면 해시와 서명을 다시 인수한다.

### 별도 승인 이후

1. 소유자와 공개 범위를 확인하고 공개 저장소를 준비한다. 기본 브랜치 직접 쓰기와 승인 없는 워크플로 변경을 제한한다. 검토 완료된 최초 소스 커밋만 Push한다. 제출자와 별도의 승인자를 쓸 수 있는 경우 승인자를 지정한다. Issues와 비공개 보안 보고 수단을 설정한다.
2. GitHub Actions를 사용할 경우 승인된 기본 브랜치와 소유자만 수동 실행한다. 서명은 보호된 환경 `release-signing`의 필수 검토자 승인을 거치거나 로컬에서 진행한다. 보호 환경 사용 전 운영 개인키의 이전 여부는 별도로 승인한다. 첫 공개에는 로컬에서 인수한 7파일을 그대로 쓸 수 있다.
3. 태그와 초안·공개 릴리스의 충돌을 `scripts/check-release-slot.py`로 확인한다. 검토한 커밋을 대상으로 **하나의 v1.0.0 초안**을 준비한다. 같은 이름이 있으면 중단하고 기존 작업과 대조한다. 자동 덮어쓰기와 같은 버전 재발행은 하지 않는다.
4. **초안에만** 7파일을 업로드한다. 모든 다운로드가 끝날 때까지 초안으로 유지하고, 자산명·개수·바이트·SHA-256을 승인 목록과 대조한다. 인증된 초안 다운로드로 독립된 폴더에 받아 `--signed`와 `-VerifyOnly`를 재실행한다. 일부만 올라갔거나 지문이 다르면 공개를 보류한다. 정상 초안의 자산만 대상으로 누락분을 보완하거나 새 버전을 정한다.
5. 버전·커밋·릴리스 노트·공개 코드·전체 파일 목록을 승인권자가 최종 확인한 뒤 정식 최신 Stable로 게시한다. 이후 익명 클라이언트가 latest/download에서 인덱스·서명·패키지를 받는지 실제 GitHub CDN에서 확인한다. 게시 직후 동일 1.0.0 설치본은 ‘최신’이 정상이다. **시험 후속 버전은 게시하지 않는다.** 실제 업데이트 적용은 다음 승인된 정식 버전으로 인수한다.
6. 장애가 있으면 새 다운로드와 채널 안내를 중단하고 원인과 안전한 설치 버전을 알린다. 이미 설치한 사용자에게 같은 태그의 아티팩트를 교체해 다른 내용을 전달하지 않는다. 수정된 새 버전으로 복구한다.

공식 주소 조회·태그와 초안 충돌 확인·검토자 승인은 운영 절차다. 초안 검증과 공개 CDN에서 수행한 인수 결과를 구분해 기록한다.
