# Stable 업데이트 서명키 관리

운영 키는 ECDSA NIST P-256이다. 키 식별자는 DER SubjectPublicKeyInfo 전체의 SHA-256이다. 제품에는 공개키만 내장한다. SHA-256 지문과 서명의 역할, Windows 게시자 서명은 별개다. [운영 검증키 기록](update-trust.json)

### 보관과 서명

로컬 키 도구는 운영자 Windows 계정의 영구 응용 프로그램 데이터 아래 별도 SonoHUD.ReleaseSigning 폴더에 **DPAPI CurrentUser로 암호화한 PKCS#8**을 생성한다. 키 폴더의 접근 주체는 해당 계정과 SYSTEM이다. 다른 사용자·새 PC로 암호문 파일만 옮겨서는 복구할 수 없다. 이 보호는 서명 계정 자체가 탈취된 경우까지 막지 못한다. 개인키나 그 Base64를 로그·채팅·명령행·소스·배포 폴더에 출력하지 않는다.

`./scripts/Manage-ReleaseKey.ps1`로 기존 키의 공개 기록을 읽는다. 최초 프로비저닝만 `-Create`로 실행한다. 기존 키를 덮어쓰지 않는다. 공식 소스의 update-trust.json과 keyId·publicKey를 대조한다. 로컬 서명은 `Sign-ReleaseFeed.ps1 -Directory <심사한 폴더> -PublicKey <SPKI> -WindowsUserKey`로 수행한 뒤 `-VerifyOnly`로 새 프로세스에서 확인한다.

### 독립 백업과 복구

키 소유자가 오프라인 매체와 암호 관리 수단을 준비한다. `Manage-ReleaseKey.ps1 -BackupPath <오프라인매체의-새파일>`에서 암호를 대화형으로 입력한다. AES-256 및 PBKDF2-SHA256으로 암호화한 PKCS#8만 저장한다. 암호는 매체와 분리해서 보관한다. 새 Windows 프로필에서 `-RestorePath <백업파일>`로 복호화·재보호하고 **기존 공개키 지문과 일치**하는지 확인한다. 운영 키가 이미 있는 계정에는 복원하지 않는다. 온라인 자동 서명이 꼭 필요하다면 별도 승인된 비밀 보관·전달 절차를 사용한다. 소유자 승인 전 GitHub에 키를 등록하지 않는다.

### 키 교체·분실·유출

계획된 교체는 기존 키로 서명한 **두 공개키를 모두 신뢰하는 중간 버전**을 먼저 배포한다. 충분히 전환한 뒤 새 키로 서명하고 후속 버전에서 기존 키를 제거한다. 키가 분실되면 오프라인 백업 복구와 지문 확인을 우선한다. 복구할 수 없거나 유출이 의심되면 서명·배포를 즉시 중지하고 공식 저장소에서 영향 버전·대안과 새 지문을 독립적으로 안내한다. 손상된 키로 신뢰를 조용히 초기화하지 않는다. 안전한 기존 키가 없다면 새 설치기를 통한 명시적 수동 재설치가 필요하다.
